# Redictum Terminal v1.0 — Design Document

> Work in progress. Формируется через диалог.

---

## Назначение

Системная утилита voice-to-text для Linux. Захват хоткеев, запись с микрофона, транскрипция через whisper.cpp, вставка текста в активное поле ввода.

## Фичи v1.0

1. **Один скрипт** — `redictum`, единственная точка входа
2. **Самодиагностика** — проверка всех зависимостей при запуске
3. **Автоустановка** — системные пакеты (apt), Python-пакеты (pip), whisper.cpp (git + cmake + модель)
4. **Валидация конфига** — проверка config.json на корректность
5. **Два режима запуска** — интерактивный и демон (start/stop/status)
6. **--version** — вывод версии скрипта
7. **Push-to-talk** — одна кнопка (Insert), без модификаторов
8. **Запись аудио** — через arecord
9. **Нормализация** — ffmpeg loudnorm
10. **Транскрипция** — whisper.cpp с поддержкой prompt
11. **Авто-вставка** — xdotool Ctrl+V с сохранением буфера обмена
12. **Звуковые уведомления** — paplay (старт записи, транскрипция, готово)
13. **Логирование транскрипций** — дневные файлы в `transcripts/`
14. **Логирование приложения** — ошибки/статус демона в `logs/`
15. **Ротация аудио** — хранение последних N файлов, старые удаляются
16. **Graceful shutdown** — корректное завершение при SIGTERM/Ctrl+C
17. **Красивый UI** — rich (цвета, спиннеры, иконки)

## Команды

Один файл: `redictum` (без .py, shebang `#!/usr/bin/env python3`, chmod +x). CLI: `argparse`.

| Команда | Что делает |
|---------|-----------|
| `redictum` | Диагностика → интерактивный режим |
| `redictum start` | Диагностика → запуск демона |
| `redictum stop` | Остановка демона |
| `redictum status` | Работает демон или нет |
| `redictum whisper` | Мастер установки whisper.cpp (install / check / reconfigure) |
| `redictum --help` | Подсказка по командам |
| `redictum --version` | Вывод версии |

- При каждом запуске (`redictum` и `start`) — сначала диагностика: зависимости, конфиг, пути. Если проблемы — предлагает исправить, не продолжает.
- `stop` и `status` — без диагностики, работают только с PID-файлом.

## Демонизация

- **Механизм:** двойной fork + PID-файл
- **PID-файл:** `redictum.pid` (рядом со скриптом)
- **start:** двойной fork → отвязка от терминала → запись PID
- **stop:** чтение PID из файла → SIGTERM → удаление PID-файла
- **Защита:** проверка PID-файла при запуске (не запускать дважды)
- **Работает на любом Linux, без внешних зависимостей**

## Звуковые уведомления

- Генерация WAV-звуков в коде (модуль `struct`, синусоида)
- Никаких внешних звуковых файлов — всё встроено в скрипт
- Разные тона для разных событий:
  - Старт записи — низкий тон
  - Транскрипция — средний тон
  - Готово — высокий тон
- Воспроизведение через `paplay`
- Звуки генерируются на лету или кешируются при первом запуске

## Graceful Shutdown

- Перехватываем SIGTERM и SIGINT (Ctrl+C)
- Если идёт запись → останавливаем, удаляем незаконченный файл
- Если идёт транскрипция → ждём завершения, потом выходим
- Удаляем PID-файл (если демон)
- Интерактивный режим: Ctrl+C для выхода (без специального хоткея)

## Зависимости

Принцип: subprocess + системные утилиты. Минимум Python-пакетов.

| Тип | Что | Назначение | Установка |
|-----|-----|------------|-----------|
| Python | `pynput` | Глобальные хоткеи | `pip install pynput` |
| Python | `rich` | Красивый вывод в терминал (цвета, спиннеры, иконки) | `pip install rich` |
| Система | `alsa-utils` | Запись звука (`arecord`) | Обычно предустановлен |
| Система | `ffmpeg` | Нормализация аудио | `apt install ffmpeg` |
| Система | `xclip` | Буфер обмена | `apt install xclip` |
| Система | `xdotool` | Авто-вставка (Ctrl+V) | `apt install xdotool` |
| Система | `pulseaudio-utils` | Воспроизведение звуков (`paplay`) | Обычно предустановлен |
| Внешнее | `whisper.cpp` | Транскрипция | Ручная сборка |

### Диагностика при запуске (два этапа)

**Этап 1 — критические проверки (fail fast).**
Без этого работа невозможна, автоустановка не предусмотрена:
- Python 3.10+
- Linux (не macOS/Windows)
- PulseAudio (`paplay`) — звук
- ALSA (`arecord`) — запись
- X11 (`DISPLAY`) — хоткеи и clipboard

Если что-то отсутствует — понятное сообщение и выход.

**Этап 2 — устанавливаемые зависимости (auto-fix).**
Предлагаем установить, пользователь подтверждает:
- Системные: `ffmpeg`, `xclip`, `xdotool` → `sudo apt install ...`
- Для сборки whisper: `cmake`, `build-essential`, `git` → `sudo apt install ...`
- Python: `pynput`, `rich` → `pip install pynput rich`
- Поддержка: apt (Debian/Ubuntu/Mint). Остальные дистрибутивы — инструкция для ручной установки

**whisper.cpp** — смарт-визард (`./redictum whisper`), три режима:

*Установка (whisper не найден):*
  1. Проверяем CUDA toolkit: версия 12+ обязательна для GPU-сборки
  2. Если GPU есть, но CUDA нет/старая → предлагаем установить из NVIDIA apt-репо
  3. `git clone --depth 1 https://github.com/ggerganov/whisper.cpp`
  4. Сборка с CUDA (если доступна) или CPU-only (fallback при ошибке)
  5. Выбор модели: 7 вариантов (от tiny до large-v3), дефолт large-v3-turbo-q5_0
  6. Скачивание модели с Hugging Face (curl/wget)
  7. Прописываем пути в config.json (с ~ для читаемости)

*Проверка (whisper найден):*
  1. Определяем: собран с CUDA или CPU-only (через ldd)
  2. Если CPU-only, а CUDA доступна → предлагаем пересобрать
  3. Если CUDA недоступна, но есть GPU → предлагаем установить тулкит
  4. Проверяем наличие модели, предлагаем скачать если нет

*При диагностике (./redictum, ./redictum start):*
  - Если whisper не найден → предлагаем установить с y/n
  - Если найден → ✓, продолжаем

## Конфигурация

- **Формат:** JSON (`config.json`, рядом со скриптом)
- **Чтение:** `json` (встроен в Python)
- **Python:** 3.10+
- **Расположение:** папка проекта (не `~/.config/`)
- **Концепция:** easy to use, simple — только то, что реально нужно менять
- **Тильда `~`:** поддерживается в путях

### Приоритет настроек

1. Все дефолты захардкожены в коде (single source of truth)
2. При первом запуске генерируется config.json со ВСЕМИ параметрами и их дефолтами
3. Пользователь меняет только то, что хочет
4. При чтении: значение из конфига > дефолт из кода (fallback)
5. Если параметра нет в конфиге — берётся дефолт

### config.json (генерируется из дефолтов)

```json
{
  "whisper_cli": "",
  "whisper_model": "",
  "whisper_language": "en",
  "whisper_prompt": "",
  "text_prefix": "",
  "text_postfix": " ",
  "sample_rate": 16000,
  "transcription_timeout": 120,
  "hold_delay": 1.0,
  "max_audio_files": 10,
  "sound_volume": 50
}
```

## Тестирование

- **Фреймворк:** `pytest`
- **Принцип:** логика отделена от системных вызовов, тестируем только логику

### Покрываем тестами

- Парсинг и валидация config.json (валидный, битый, пустой, без файла)
- Раскрытие `~` в путях
- Диагностика зависимостей (мок `shutil.which`)
- Логика PID-файла (создание, чтение, проверка, удаление)
- Ротация аудиофайлов
- Сборка текста (prefix + text + postfix)
- Парсинг аргументов
- Логирование транскрипций (формат записи)

### Не тестируем автоматически

Запись звука, хоткеи, clipboard, xdotool, paplay, whisper — только ручное тестирование.

### Чистая установка через Docker

Dockerfile на базе Ubuntu 22.04/24.04 + Python 3.10, без предустановленных зависимостей. Позволяет каждый раз воспроизвести установку с нуля.

Что проверяем в Docker:
- Самодиагностика и автоустановка зависимостей (apt, pip)
- Валидация конфига
- Парсинг аргументов, --help
- pytest тесты

Что только на живой системе:
- Запись звука, хоткеи, clipboard, xdotool, paplay, whisper

## Установка для пользователей

Один файл — и всё. Скрипт при первом запуске сам создаёт config.json (дефолтный), audio/, transcripts/, logs/.

```bash
curl -fsSL https://raw.githubusercontent.com/.../redictum -o redictum && chmod +x redictum
./redictum
```

- Не нужен install.sh, архивы или дополнительные файлы
- Дефолтный конфиг хранится в коде, сериализуется в JSON при первом запуске
- Вся автоустановка зависимостей — при первом запуске
- Не требуется ни pip, ни apt-репозиторий

## Качество кода

Open source проект — код должен быть образцовым.

- **PEP 8** — стиль, нейминг, отступы
- **Type hints** — везде, включая возвращаемые типы
- **Docstrings** — Google style, для всех публичных функций/классов
- **Чистая архитектура** — логика отделена от I/O, классы с единственной ответственностью
- **Линтеры/форматтеры:** `ruff` (линтинг + форматирование в одном инструменте)
- **Константы** — именованные, без magic numbers
- **Обработка ошибок** — типизированные исключения, не голые `except:`

## Addendum: изменения после согласования дизайна

Ниже — изменения, внесённые в процессе реализации (итерации 1–8). Основной дизайн выше не менялся.

### Конфигурация: JSON → YAML

- `config.json` заменён на `config.yaml` (вложенная 3-уровневая структура с комментариями)
- Добавлена зависимость `PyYAML` (автоустановка через pip)
- Формат конфига:
  ```yaml
  whisper:
    cli: "~/whisper.cpp/build/bin/whisper-cli"
    model: "~/whisper.cpp/models/..."
    language: "auto"
    prompt: "Hello. Umm, let me think. So,"
  audio:
    sample_rate: 16000
    max_files: 10
  # ...
  ```

### Режим перевода (Translate mode)

- `Ctrl+Insert` — запись + перевод на английский через `whisper.cpp --translate`
- Ключевые ограничения whisper.cpp:
  - `--translate` + `-l` = сломано (выдаёт язык `-l`, не английский)
  - `--translate` + `--prompt` = сломано (prompt перебивает translate)
  - Корректная работа: `--translate` без `-l` и без `--prompt`

### Автодетект языка

- Параметр `language: "auto"` → определяется из системной локали (`LANG` env var)
- Дефолтный prompt — на английском, работает с `-l ru` в режиме transcribe

### Git → Tarball

- Зависимость от `git` полностью убрана
- whisper.cpp скачивается как tarball с GitHub Releases (curl/wget + tar)
- Версия whisper.cpp зафиксирована (v1.8.3)

### Звуковые уведомления (финальные)

4 события вместо 3, конкретные тона:
- START = #13 (тройной бип)
- PROCESSING = #04 (металлический тик)
- DONE = #14 (стеклянный тап)
- ERROR = #12 (низкий гул)

### Буфер обмена

- Универсальное сохранение/восстановление через X11 TARGETS
- Поддержка текста, изображений и бинарных данных

### --config флаг

- `./redictum --config start` — пересоздаёт config.yaml перед запуском
- Debug/maintenance опция, не документирована в --help

### Баг: stale config при первой установке

- При первом запуске `init()` загружал конфиг до `check_whisper()`, который обновлял пути на диске
- Фикс: `init()` перечитывает config.yaml после завершения всех проверок (`return self._config_mgr.load()`)
