# BUG: 200ms на восстановление clipboard может быть мало

> Дата: 2026-02-20
> Источник: code review
> Статус: анализ
> Приоритет: средний

## Проблема

После `clipboard.paste()` (xdotool Ctrl+V) ждём 200ms и восстанавливаем clipboard. На нагруженной системе, через SSH/VNC или в тяжёлом приложении paste может не успеть обработаться — и приложение получит уже восстановлённое старое содержимое буфера вместо транскрипции.

## Код

Строки ~2165-2169:
```python
clipboard.copy(final_text)
clipboard.paste()
time.sleep(0.2)              # ← 200ms хватит?
if saved:
    clipboard.restore(saved)
```

## Варианты фикса

**A.** Сделать задержку настраиваемой в конфиге:
```yaml
clipboard:
  paste:
    restore_delay: 0.3    # секунды
```

**B.** Увеличить дефолт до 300-500ms.

**C.** Не восстанавливать clipboard вообще (опция `preserve: false`).

Рекомендация: A + увеличить дефолт до 300ms.
