# BUG: Чувствительная информация попадает в логи

> Дата: 2026-02-20
> Источник: анализ логов
> Статус: анализ

## Проблема

Транскрибированный текст пишется в лог целиком. Пользователь не может отправить лог для отладки, потому что там вся его речь: пароли, личные сообщения, рабочие переписки.

### Сейчас

```
[INFO] Transcribed (mode: transcribe): 'Вика, добрый день. Какой прогноз?'
```

Всё, что пользователь произнёс — в открытом виде в файле `logs/redictum.log`.

## Фикс

По умолчанию в лог пишется только количество символов, без самого текста:

```
[INFO] Transcribed (mode: transcribe): 53 chars
```

Для отладки можно включить полный вывод через конфиг:

```
[INFO] Transcribed (mode: transcribe): 53 chars — 'Вика, добрый день. Какой прогноз?'
```

### Конфиг

```yaml
logging:
  # Write transcribed text to log (disable for privacy)
  log_transcriptions: false     # default: false (safe)
```

### Код

```python
if self._log_transcriptions:
    log.info("Transcribed (mode: %s): %d chars — '%s'", mode, len(text), text)
else:
    log.info("Transcribed (mode: %s): %d chars", mode, len(text))
```

### Что ещё может быть чувствительным

- Транскрибированный текст — основная проблема
- Имена файлов (содержат только таймстамп — безопасно)
- Язык, режим, PID — безопасно

### Transcripts

Дневные файлы в `transcripts/` — там текст нужен по дизайну (это и есть архив транскрипций). Но пользователь о них знает и сам решает, отправлять или нет.

## Приоритет

Высокий — вопрос приватности. Дефолт должен быть безопасным.
